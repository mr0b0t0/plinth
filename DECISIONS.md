# Decisions

Choices made where the spec ([docs/spec.md](docs/spec.md)) or the build prompt
([docs/build-prompt.md](docs/build-prompt.md)) left room. Newest last. Mark anything a human should
review with **Review**.

| Date | Decision | Why |
| --- | --- | --- |
| 2026-11-13 | Turborepo on a pnpm workspace. Workspaces: `apps/worker`, `apps/web`, `packages/shared`, `e2e`. `migrations/` and `docs/` sit at the root and are not packages | Matches the build prompt's required layout. Turbo caches typecheck, build and test per package |
| 2026-11-13 | Root scripts call `turbo run <task>` for `build`, `dev`, `typecheck`, `test`, `test:e2e`. A package joins a task by defining that script; packages without it are skipped | One entry point for the quality gates the build prompt names |
| 2026-11-13 | `@plinth/shared` is consumed as TypeScript source (`exports` points at `src/index.ts`), with no build step | The Worker (wrangler/esbuild) and the web app (Vite) both bundle TS directly; a build step adds nothing |
| 2026-11-13 | Biome 2.6.6 for lint and format, run once at the root (`pnpm lint`, `pnpm format`), not per package through Turbo. Markdown is excluded | One fast tool, no ESLint/Prettier config to keep in step. Biome's Markdown formatter pads tables to a single width, which makes prose docs unreadable in diffs |
| 2026-11-13 | TypeScript 7.0.2 (the native compiler), strict, with `noUncheckedIndexedAccess`. Shared settings in `tsconfig.base.json` | Current stable release. **Review** if a tool added later needs the TypeScript 6 JS API; drop to 6.0.3 in that case |
| 2026-11-13 | pnpm pinned to 10.27.0 through `packageManager`, the version installed on the dev machine. Node `>=22` | pnpm 12 is current; upgrading is a separate, deliberate step. **Review** |
| 2026-11-13 | Dependency versions pinned exactly, and only releases at least a week old | Reproducible installs and a buffer against compromised fresh releases |
| 2026-11-13 | D1 migrations live in the root `migrations/`; wrangler in `apps/worker` should point `migrations_dir` at `../../migrations` | The build prompt puts `migrations` at the top level |
| 2026-11-13 | Node 24.22.2 pinned per project with pnpm `use-node-version` in `.npmrc`; engines `>=22.12` | Vitest 5 and the Workers Vitest plugin do not support Node 23 (the machine's default). Project-scoped, nothing global changes |
| 2026-11-13 | MCP SDK v2 (`@modelcontextprotocol/server` and `/client` 2.4.0) instead of v1 `@modelcontextprotocol/sdk` | v2 is the current stable line (2026-07-28 spec), web-standard (`createMcpHandler(...).fetch`), no Express. It still serves 2025-era clients through its stateless legacy fallback. **Review** |
| 2026-11-13 | `@cloudflare/vitest-plugin` 1.6.0 with Vitest 5.1.0 | `@cloudflare/vitest-pool-workers` is deprecated and renamed; 1.6.0 pins the same wrangler (4.158.0) the worker uses |
| 2026-11-13 | OAuth server, rate limits and single-use nonces are implemented on D1, not KV or Durable Objects | `@cloudflare/workers-oauth-provider` needs KV. Keeping D1 as the only store means self-hosting and staging need exactly one Worker, one D1 database and one R2 bucket |
| 2026-11-13 | Artifact ids are 20 lowercase letters/digits (a DNS label, ~103 bits); slugs are a kebab title plus 10 random characters | The id is the content subdomain. Slugs stay readable but unguessable enough for "anyone with the link" |
| 2026-11-13 | Tools and endpoints accept an artifact id or slug wherever `id` appears | Agents and people both have one or the other at hand |
| 2026-11-13 | `publish_artifact` also accepts optional `password` and `emails` | Otherwise publishing with `password` or `allowlist` visibility would create an artifact nobody can open until a second call |
| 2026-11-13 | `update_artifact` without `assets` carries the current version's assets forward; with `assets` (even `[]`) it replaces them | Agents usually edit only the HTML |
| 2026-11-13 | New versions: insert the `versions` row first (UNIQUE(artifact_id, number) picks one winner), then write R2 under a fresh prefix, then advance `current_version` | No two writers can share a prefix, so stored versions are never overwritten; a stale `base_version` loses with a conflict |
| 2026-11-13 | Schema additions beyond the spec: `artifacts.access_epoch`, `updated_at`, `taken_down_at`; `versions.manifest`, `restored_from`; `users.email_verified_at`, `is_admin`; tables `oauth_requests`, `rate_limits`, `used_nonces`, `dev_outbox` | Epoch: any visibility, password or grant change invalidates every outstanding content cookie and password pass. The rest support takedown, restore labels, public-visibility gating, consent screens and rate limits |
| 2026-11-13 | Viewer flow: app checks access, issues a 60-second single-use signed token (artifact id + access epoch + nonce), the artifact subdomain exchanges it at `/__plinth/enter` for a 12-hour `HttpOnly; Secure; SameSite=None; Partitioned` host-only cookie | The artifact is framed cross-site by the app, so the cookie must be `SameSite=None`; `Partitioned` (CHIPS) keeps it working where third-party cookies are blocked |
| 2026-11-13 | Artifact iframes use `sandbox="allow-scripts allow-same-origin allow-forms allow-popups allow-popups-to-escape-sandbox allow-modals allow-downloads"`, never `allow-top-navigation` | The frame's origin is the artifact's own content subdomain (a different site from the app), so `allow-same-origin` gives it its own origin and storage, never the app's. Many artifacts use localStorage. **Review** |
| 2026-11-13 | Content CSP allows `'unsafe-eval'` and `'wasm-unsafe-eval'` for scripts, and `'self'` (the artifact's own files) for scripts, styles, fonts and media in addition to the spec's list | Common artifact libraries need eval; it does not widen network reach, which `connect-src 'self'`, `form-action 'self'` and `default-src 'none'` still block. **Review** |
| 2026-11-13 | CSRF: double-submit cookie (`plinth_csrf`, `SameSite=Strict`) plus an `Origin` check on every state-changing `/api/v1` request without a bearer token, including anonymous ones | Session cookies are already `SameSite=Lax`; this also covers login CSRF and the viewer password form |
| 2026-11-13 | Who can do what: owner everything; editor view/comment/mention/edit/restore; commenter view/comment/mention; viewer view. Grant holders skip the password. Strangers get 404, not 403. Agents act as their user, limited by token scopes (`artifacts:read`, `artifacts:write`, `mentions`) | Encoded once in `apps/worker/src/policy.ts` |
| 2026-11-13 | Instance admins (emails in `ADMIN_EMAIL`) may view any non-deleted artifact, including taken-down ones, to review reports | A takedown decision needs to see the content. **Review** |
| 2026-11-13 | `ENVIRONMENT` var (`development`, `staging`, `production`). Production refuses: shared registrable domain for app and content hosts, `STAGING_CONTENT_FALLBACK`, http, and the `console` email provider (it logs sign-in links) unless in single-user mode | "Refuse to run in production mode" from the build prompt, plus the secrets-in-logs rule |
| 2026-11-13 | The web app uses a ~70-line history router instead of a router library | Fewer dependencies; the app has a fixed, small route table |
| 2026-11-13 | Work happens on branch `v1-build`, not `main` | Repo rule: branch before committing on the default branch |
| 2026-11-13 | Sign-in: a new email supersedes the previous code and link; 5 wrong guesses per code plus per-email and per-IP hourly limits; login answers identically for every address. In single-user mode only `ADMIN_EMAIL` can sign in | No account enumeration; brute force on six digits is bounded |
| 2026-11-13 | Per-IP rate limits are skipped when `cf-connecting-ip` is absent | Cloudflare always sets it in production; local tests do not |
| 2026-11-13 | OAuth: public clients only (`token_endpoint_auth_method` forced to `none`), PKCE S256 required, exact redirect URI match, redirect URIs must be https or http on loopback. Custom-scheme redirect URIs are refused | Simplest safe OAuth 2.1 profile. **Review**: desktop clients that need `myapp://` callbacks will not connect |
| 2026-11-13 | OAuth: each consent creates a new labelled connection; refresh tokens rotate and reusing a rotated one revokes the grant (migration 0002); reusing an authorization code revokes the grant; revoking a token revokes its connection | OAuth 2.1 guidance; one connection per agent the user approved |
| 2026-11-13 | Admin CLI: `pnpm --filter @plinth/worker admin -- set-limit <email> <n|default> --local|--remote` runs `wrangler d1 execute` | Per-user quota override from the build prompt without an admin UI |
| 2026-11-13 | Allowlist viewers confirm an email by six-digit code; the response is identical whether or not the email is listed, and the code is sent after the response | No enumeration of the allowlist, including by timing |
| 2026-11-13 | Admin rights follow the current `ADMIN_EMAIL` list on every request, not the stored `users.is_admin` flag | Removing an admin takes effect immediately |
| 2026-11-13 | A browser's confirmed viewer email counts for grants alongside a user session with a different email; the stronger role wins | Found in review: a signed-in person who confirmed a listed email lost that access outside the gate |
| 2026-11-13 | Reports: anyone who can view may report (rate limited per IP); "actioned" takes the artifact down immediately (epoch bump) and closes its other reports; decided reports are final and there is no un-takedown endpoint in v1 | Smallest takedown flow that satisfies the hosted-instance requirement. **Review** |
| 2026-11-13 | `X-Robots-Tag: noindex, nofollow` on content responses except public artifacts on instances with public visibility on | Unlisted links should not be indexed |
| 2026-11-13 | With `STAGING_CONTENT_FALLBACK` the content CSP adds `sandbox` without `allow-same-origin`, so artifact script on the app origin gets an opaque origin | The fallback serves user HTML on the app host; this keeps it away from app cookies and APIs. Staging only, and localStorage, preview and comment pins degrade there |
| 2026-11-13 | Mentions: comments written by an agent connection never create tasks; `@claude`/`@codex` win over a connection label with the same handle; `done` requires a `result_version` newer than the comment's version | Prevents agent loops and keeps "an agent's result is always a new version plus a reply" |
| 2026-11-13 | Comments render through an escape-first Markdown subset in `packages/shared/src/markdown.ts` (no raw HTML, links only http/https/mailto) instead of a sanitizer library | Small, dependency-free, testable in any runtime |
| 2026-11-13 | People with no role on an artifact (link or password viewers) see comment authors by name or address local part, not full email | Avoids exposing collaborators' emails to anyone with the link. **Review** |
| 2026-11-13 | All list endpoints return `{ items: [...] }` | One shape for every list, room for paging later |
| 2026-11-13 | Hosted instance and staging send email as `EMAIL_FROM="Plinth <noreply@aconite.io>"` through SendGrid. `noreply@plinth.aconite.io` was rejected by SendGrid (not a verified sender identity); `aconite.io` is verified in Aconite's account. A test email through the real adapter was accepted on 2026-11-13 | German's choice. Authenticating `plinth.aconite.io` in SendGrid later would allow a product-specific sender |
| 2026-11-13 | `DEV_IGNORE_CLIENT_IP=true` (honoured only when `ENVIRONMENT=development`) drops per-IP rate limits; per-email limits still apply. The e2e server sets it | `wrangler dev` sends `CF-Connecting-IP`, and the full e2e suite signs in far more than 20 times an hour from one address |
| 2026-11-13 | If advancing `current_version` fails after a version row is inserted, the write is retried three times and then the row and its files are removed | Found in e2e under SQLite locking: an orphan row made every later `base_version` update a false conflict |
| 2026-11-13 | The artifact page has its own slim top bar (no app shell above the frame); gates, report and legal pages use the public shell; the frame background is plain white in both modes, like a browser tab | The exhibit is the point; many artifacts set no background of their own |
| 2026-11-13 | Each fresh viewer gate creates a new iframe element instead of changing `src` | No history entries inside the frame; one-time tokens stay one-time |
| 2026-11-13 | On small screens the artifact actions fold into a menu, but the Comments toggle stays visible | Commenting is a primary action; found by the integrated e2e run |
| 2026-11-13 | The "allowlist" visibility is labelled "Specific people" in the UI | Plain words for viewers and owners; the API keeps `allowlist` |
| 2026-11-13 | New personal access tokens default to client type "Other" | An `@claude`/`@codex` mention should never reach a token by accident |
| 2026-11-13 | Settings: visibility and password save with an explicit "Save access" button; people changes apply immediately with an undo toast; delete requires typing the title | Access changes end existing viewer sessions, so they deserve a deliberate step |
| 2026-11-13 | Version diff: only the changed middle is diffed, with a 400 ms / 4,000-line budget after which the region is shown as removed-then-added; rows render in pages of 1,500 | Keeps 5 MB documents responsive (measured ~0.9 s for 5,000 lines) |
| 2026-11-13 | Editor preview: a static loader on the artifact's own subdomain (`/__plinth/preview`) receives HTML by origin-checked `postMessage` and writes it; each re-render reloads the loader | The preview runs under the exact content CSP and origin of the published artifact; no `srcdoc` (which would inherit the app's CSP), no loosened sandbox. Disabled in the staging path fallback |
| 2026-11-13 | Monaco is bundled locally with only the editor and HTML workers, loaded lazily on the editor page | The app CSP forbids CDNs; the rest of the app stays small |
| 2026-11-13 | Comment pins: only open anchored threads get pins, numbered in creation order; the app accepts a bridge `pick` only while it asked for one, and validates every field of every message | Artifact scripts share the frame's origin and can forge bridge messages |
| 2026-11-13 | Legal pages are clearly marked templates with placeholder fields for the operator | Required as placeholders by the build prompt; text must come from the operator's counsel. **Review** |
| 2026-11-13 | `POST /__dev/seed` (development and `DEV_SEED=true` only) creates users, tokens and sessions for the e2e suite | Writing the local SQLite file from a second process caused `SQLITE_BUSY` under parallel tests |
| 2026-11-13 | Mentions in pull mode use the owner's own agent connection; there is no separate token scoped to one artifact. The spec's "agent tokens used for mentions are scoped to that one artifact" is implemented when push mode (platform-minted tokens) is built | In pull mode the agent already holds the owner's authority through its own connection; what keeps a mention from escalating is that comment text is untrusted (every tool description says so) and only the owner's agents can see tasks. **Review** |
| 2026-11-13 | The staging path fallback (`STAGING_CONTENT_FALLBACK`) serves user HTML from the app host under `/__content/<id>/`, sandboxed by CSP with an opaque origin; it is refused in production | The only way to stage on `workers.dev`, which has no wildcard subdomains. It is an explicit, staging-only exception to "user HTML never runs on the app host". **Review** |
| 2026-11-13 | Per-account storage cap `MAX_STORAGE_BYTES_PER_USER` (default 1 GiB) across every version of the owner's live artifacts; editors' saves count against the owner | The spec caps storage; versions are immutable, so storage grows with every save |
| 2026-11-13 | The artifact quota is enforced by a conditional `INSERT ... WHERE count < limit`, so parallel publishes cannot overshoot it | Found in review |
| 2026-11-13 | A claimed mention task can be claimed again 30 minutes after the claim if it was never completed | An agent that crashes mid-task must not leave the request stuck forever |
| 2026-11-13 | Reports and the admin takedown page are on for every instance (only public visibility has a flag); legal pages are templates whose operator name is a placeholder field | Reporting is useful anywhere and costs nothing when unused; operators must replace the legal text anyway. **Review** |
| 2026-11-13 | No public listing page (e.g. an owner profile) in v1; `ALLOW_PUBLIC_VISIBILITY` only unlocks the `public` visibility | The spec says public artifacts "may be listed"; listing is additive later. **Review** |
| 2026-11-13 | The magic-link page removes the token from the address bar and history as soon as it loads, keeping it in memory until "Sign in" | Keeps the sign-in secret out of browser history (the one-time viewer token is the only allowed URL secret) |
| 2026-11-13 | One shared `ARTIFACT_IFRAME_SANDBOX` constant in `packages/shared` for every artifact frame | One place to audit |
| 2026-11-13 | `docs/build-prompt.md` updated to the current brief (adds "Working in parallel" and build step 10) | AGENTS.md: the repo copy must match the brief in use |
| 2026-11-13 | Artifacts render only inside the app's frame: a top-level visit to a content host (`Sec-Fetch-Dest: document`) is redirected to `APP_HOST/a/<id>` (version or sub-path kept), and `/open/:id` forwards there. Inside the frame, an expired session answers 401 "reload" | Found in the security audit: opened top-level, an artifact could navigate away carrying what the viewer typed. Framed, the sandbox (no top navigation) and the app's `frame-src` stop that. Direct content links still work; they just show the artifact framed. **Review** |
| 2026-11-13 | Content hosts refuse service-worker script requests and send `Clear-Site-Data: "storage"` for deleted or taken-down artifacts | Security audit: a service worker kept serving a deleted artifact and could intercept enter tokens |
| 2026-11-13 | WebRTC is a known, documented exfiltration gap (no CSP directive browsers enforce covers STUN/TURN) | Nothing in the platform's control closes it today; documented in docs/security.md |
| 2026-11-13 | Mention tasks carry `comment_author_email` and `comment_author_role` (server-derived); display names cannot contain `@` | Security audit: a commenter could set a display name that looked like the owner to the owner's agent |
| 2026-11-13 | People without a role on an artifact (link viewers) do not see the owner's email or ids, or authors' full emails, in artifact and version responses | Security audit; matches how comments already hide addresses |
| 2026-11-13 | Password attempts are capped per artifact across all addresses (100 an hour) as well as per address (10) | Security audit: guessing could be spread over many IPs |
| 2026-11-13 | Admins may view an artifact only if it has a report (open or decided) | Security audit; narrows the earlier "admins may view any artifact" Review item |
| 2026-11-13 | The magic link carries its token in the URL fragment (`/login/magic#token=`), so it never reaches the server or its request logs | Security audit: Workers Logs record full request URLs |
| 2026-11-13 | Config refuses `ENVIRONMENT=development` unless `APP_HOST` is a localhost name, refuses staging with app and content on one registrable domain unless the path fallback is on, and refuses equal `SESSION_SECRET` and `TOKEN_SIGNING_KEY` | Security audit: development turns on unauthenticated helpers |
| 2026-11-13 | `/api/v1` request bodies are capped at 40 MB | Security audit: bodies were parsed before validation with only Cloudflare's 100 MB limit |
| 2026-11-13 | The comments list returns `can_comment` and `signed_in`, and the panel says "Sign in to comment" or "view only" before anyone types | UI review: anonymous viewers were offered a composer that could not work and lost what they typed |
| 2026-11-13 | The editor shows how to make Tab move focus (Control+M, or Control+Shift+M on macOS); the diff editor names both sides and uses lighter change tints | UI review: WCAG 2.1.2 keyboard trap and axe findings in the conflict view |
| 2026-11-13 | Every app-shell page has Sign out by default, the account menu offers "Follow system theme" after a manual choice, and owners and editors are not offered "Report" in the top bar (the footer link stays) | UI review |
